# M1：模型客户端与单轮流式输出

Status: ready-for-agent

## Problem Statement

辉哥现在没有一个自己的编码 agent。日常改代码要么依赖 omp（空闲常驻内存 400–660 MB），要么手动复制粘贴到别的聊天窗口里。他想要的是一个能在终端里直接使唤、内存占用小、会话记录能用普通工具读出来的工具。

M1 解决的是最底层的缺口：**还没有任何东西能让 baize 对模型说一句话，并把这句话和模型的回答留下来。** 在这一步之前，工具、压缩、LSP、TUI 都无处挂载。

从使用者角度看，现在的问题是：他敲下 `baize "你好"` 时，什么都没有发生，因为没有程序；即使有程序，也还没有任何机制把他的问题送出去、把回答显示出来、把这段对话存到磁盘上。

## Solution

一个 Rust 二进制。读取 TOML 配置里的模型名、网关地址和上下文窗口，向 OpenAI 兼容端点发一次流式请求，把回答逐块打印到标准输出，同时把这次对话按行追加写入一个 JSONL 会话文件。

完成后，用户可以：

- 运行 `baize "解释这段代码"`，在终端里看到回答一个字一个字出现；
- 在 `~/.baize/sessions/` 下找到一个文件，用 `jq` 逐行读出刚才的问答；
- 在配置缺失、密钥错误、网关不可用时，看到一句能照着做的错误信息，而不是一串堆栈；
- 在回答生成到一半时按 `Ctrl+C`，保留已经收到的部分，并且这部分也在文件里。

这是后续所有里程碑的地基。它不调用任何工具，不做多轮对话，不压缩上下文。

## User Stories

### 首次配置与启动

1. 作为一个第一次使用的人，我希望 `baize --help` 直接列出必须配置的项和环境变量名，这样我不用翻文档就知道缺什么。
2. 作为一个第一次使用的人，我希望配置文件不存在时程序自动创建一份带注释的默认配置，这样我不需要手抄模板。
3. 作为一个第一次使用的人，我希望 `base_url` 或 `model` 缺失时启动就报错并指出是哪个字段，这样错误在发请求之前暴露。
4. 作为一个第一次使用的人，我希望 `context_window` 缺失或为 0 时启动就报错，这样后续的压缩阈值不会算错。
5. 作为一个第一次使用的人，我希望 `BAIZE_API_KEY` 不存在时，如果网关是本机地址就照常工作，这样本地无密钥网关不需要额外配置。
6. 作为一个第一次使用的人，我希望 `BAIZE_API_KEY` 不存在、网关又不是本机地址时，得到一句明确的提示，这样我知道该设哪个变量。

### 单轮对话

7. 作为一个用户，我希望 `baize "问题"` 直接把问题发给模型并显示回答，这样一条命令就能问完。
8. 作为一个用户，我希望不带参数运行 `baize` 时进入交互模式，输入一行、回车发送、看到回答后回到提示符，这样我能连续问几件事。
9. 作为一个用户，我希望在交互模式里输入 `Ctrl+D` 退出，这样有明确的结束方式。
10. 作为一个用户，我希望回答逐块出现在终端，而不是等全部生成完才显示，这样长回答时我知道它在工作。
11. 作为一个用户，我希望流式输出里没有进度条、没有 ANSI 控制字符（除换行外），这样输出重定向到文件时是干净的文本。
12. 作为一个用户，我希望回答结束后正常退出并返回 0，这样能把它放进脚本里用。
13. 作为一个用户，我希望输入为空（只有空白字符）时直接返回，不发送请求，这样误按回车不会浪费一次调用。
14. 作为一个用户，我希望输入里的中文、emoji、换行原样送达模型，这样粘贴代码和中文提问不出问题。

### 会话文件

15. 作为一个用户，我希望每次启动对话都在 `~/.baize/sessions/` 下生成一个文件，这样所有历史集中在一个地方。
16. 作为一个用户，我希望会话目录按当前工作目录编码（`/Users/xsh/gp/dotfiles` 变成 `-Users-xsh-gp-dotfiles`），这样不同项目的会话不会混在一起。
17. 作为一个用户，我希望文件名以时间戳开头、后面跟一个短随机 ID，这样目录列表按时间自然排序。
18. 作为一个用户，我希望会话文件是纯 JSONL：每行一个完整 JSON，没有包裹数组，这样 `jq -c` 能直接处理。
19. 作为一个用户，我希望文件第一行是会话头，记录 id、工作目录、创建时间、baize 版本，这样我知道这条会话发生在哪里、哪个版本。
20. 作为一个用户，我希望每条消息都带 `id` 和 `parentId`，首条消息指向会话头，这样文件本身就能组成一条链，而不需要额外索引。
21. 作为一个用户，我希望用户消息在发请求**之前**就写入磁盘，这样即使进程在等待回答时被杀，我的问题也还在。
22. 作为一个用户，我希望时间戳是带时区的 RFC3339（UTC），这样跨机器合并会话时顺序不会乱。
23. 作为一个用户，我希望模型回答里的 `usage`（输入/输出 token）在服务端提供时被记录下来，这样以后能算成本。
24. 作为一个用户，我希望 `--model` 覆盖默认模型时，文件里多一条 `model_change` 记录，这样我回看时知道这段用的是什么模型。

### 错误处理

25. 作为一个用户，我希望收到 401 时看到"鉴权失败，检查 BAIZE_API_KEY"，而不是原始响应体。
26. 作为一个用户，我希望 429 和 5xx 自动重试，间隔 1 秒、2 秒、4 秒，这样偶发限流不会打断我。
27. 作为一个用户，我希望连接超时和读取超时也按同样的规则重试，这样网络抖动不需要我手动重跑。
28. 作为一个用户，我希望三次都失败后看到一条总结性错误，并且退出码非 0，这样脚本能判断这次失败。
29. 作为一个用户，我希望 4xx（除 429 外）不重试，直接失败，这样参数错误不会被重复发送三次。
30. 作为一个用户，我希望流式输出已经开始之后再出错时不重试，只把错误写进会话并结束本轮，这样已经显示的文字不会重复出现。

### 中断

31. 作为一个用户，我希望第一次 `Ctrl+C` 停止当前生成、保留已经收到的文字，并回到提示符而不是退出进程，这样误触不会丢掉整个会话。
32. 作为一个用户，我希望 1 秒内第二次 `Ctrl+C` 直接退出进程，这样卡死时能离开。
33. 作为一个用户，我希望被中断的回答在会话文件里带一个 `interrupted: true` 标记，这样以后读到它时知道这段不完整。

### 配置与规则

34. 作为一个用户，我希望配置从 `~/.config/baize/config.toml` 读取，这样它跟着我的 dotfiles 一起管理。
35. 作为一个用户，我希望全局规则 `~/.config/baize/AGENTS.md` 追加在系统提示后面，这样我的回复偏好（中文、首词"辉哥"）对所有会话都生效。
36. 作为一个用户，我希望项目规则从当前目录向上查找最近的 `AGENTS.md`，这样我在子目录里运行也能读到仓库规则。
37. 作为一个用户，我希望优先级是内置提示 < 全局规则 < 项目规则，这样项目能覆盖全局的一般约定。
38. 作为一个用户，我希望规则文件不存在时静默跳过，不报错，这样没有规则文件的项目也能用。

### 健壮性

39. 作为一个用户，我希望会话目录不存在时自动创建，这样首次运行不需要手动 `mkdir`。
40. 作为一个用户，我希望读取会话文件时跳过损坏的半行 JSON 并在标准错误里警告，这样强杀之后文件还能打开。
41. 作为一个用户，我希望会话文件被另一个进程占用时得到明确的"已被占用"错误，而不是两边同时写入。
42. 作为一个维护者，我希望 `baize --version` 的版本号来自 `Cargo.toml`，这样不需要维护第二份。
43. 作为一个维护者，我希望 `unsafe` 代码为零，这样内存安全不依赖人工审查。

## Implementation Decisions

### 工作区结构

Cargo workspace，三个 crate，依赖方向是单向的：

- **core**：消息模型、会话（内存中的树与追加写）、系统提示组装。不依赖网络。
- **provider**：OpenAI 兼容的流式客户端、SSE 解析、重试。
- **cli**：二进制入口、参数解析、配置加载、把上面两者接起来、终端输出与信号处理。

M1 不建 `tools` 和 `lsp` crate；它们在 M2、M5 出现。

### 消息模型

会话文件是一棵用 `parentId` 连接的条目树，但 M1 只产生线性的一条链。

- `session` 条目：`id`、`cwd`、`version`、`timestamp`。没有 `parentId`，它是根。
- `message` 条目：`id`、`parentId`、`timestamp`、`message`。
- `model_change` 条目：`id`、`parentId`、`timestamp`、`model`。

`message` 的角色只有三种：`user`、`assistant`。M1 不产生 `toolResult`。

助手消息的 `message` 包含 `content`（`text` 块数组）和可选的 `usage`。中断时额外带 `interrupted: true`。这个字段不在设计文档 5.2 的示例里，是为了满足"读取时能分辨半截回答"而新增的可选字段，向后兼容。

会话头之后的第一条消息的 `parentId` 指向会话头的 `id`。叶子指针初始化为会话头的 `id`，每追加一条就前移。

### 会话存储

- 路径：`~/.baize/sessions/<编码后的目录>/<时间戳>_<8位十六进制>.jsonl`。
- 目录编码：把 `/` 换成 `-`，去掉开头的 `-`。与 omp 的编码一致。
- 文件名时间戳用 `YYYY-MM-DDTHH-MM-SSZ`（冒号换成连字符，避免文件系统差异）。
- 追加写：打开文件后保持句柄，每条消息序列化为一行、写一行、刷新。
- 加锁：打开会话文件时申请排他锁，进程正常退出时释放。锁失败返回"会话已被占用"，不重试。
- 读取：逐行解析，失败的行跳过并向标准错误输出一行警告，继续读后面的行。

### 模型客户端

`provider` 暴露一个异步 trait，只有一个方法：给定模型名、系统提示、消息列表，返回一个文本增量流。

- 请求：`POST {base_url}/chat/completions`，`stream: true`，`stream_options.include_usage: true`。
- 鉴权：`BAIZE_API_KEY` 存在时带 `Authorization: Bearer`，否则不带。
- 流解析：自己按 `data:` 行解析，忽略空行和注释行，遇到 `[DONE]` 结束。解析器必须能处理任意字节切分，包括切在一个 UTF-8 字符中间。
- 增量类型：文本、用量、结束。用量只在服务端返回时出现。
- 重试：连接错误、408、429、5xx 触发，间隔 1/2/4 秒。一旦已经向调用方交付过任何文本，就不再重试——重试会造成重复输出。
- 超时：连接 10 秒，单次读取 60 秒。

### 配置

文件 `~/.config/baize/config.toml`，只读，不写回用户文件（除首次创建默认文件）。

M1 使用的字段：`model.default`、`model.base_url`、`model.context_window`、`project.rules_file`。`context` 和 `tools` 段解析但不使用。

首次运行时如果文件不存在，写一份带注释的默认文件，使用设计文档 D9 的示例值。

`--model` 覆盖 `model.default`；如果两者不同，追加一条 `model_change`。

### 系统提示

按顺序拼接三段，用空行分隔：

1. 内置提示（固定文本，说明角色、当前工作目录、当前时间、可用工具为空）。
2. 全局规则文件内容（存在时）。
3. 项目规则文件内容（从当前目录向上找到的最近一个，存在时）。

缺失的文件静默跳过。

### 命令行

- `baize [PROMPT]`：有提示词则单轮执行，执行完退出。
- `baize`：进入交互模式，逐行读取，空行忽略，`Ctrl+D` 退出。
- `--model <NAME>`：覆盖模型。
- `--version`、`--help`：由 clap 生成。

退出码：0 成功；1 运行时失败；2 配置或用法的错误；130 被信号中断。

### 输出

- 模型文本写标准输出。
- 状态、重试提示、错误写标准错误。
- 不在标准输出里放 ANSI 控制序列。

### 中断

监听 `SIGINT`。第一次触发取消当前的请求流；如果已经有文本，按"已中断"写入会话。1 秒内第二次触发直接退出进程，退出码 130。

## Testing Decisions

### 唯一接缝

所有 M1 测试走同一条接缝：**启动真实的 `baize` 进程 + 一个本地假模型服务器**。

测试把配置里的 `base_url` 指向假服务器，把 `HOME` 指向临时目录（隔离会话文件和规则文件），然后像用户一样运行二进制，断言三样东西：标准输出文本、标准错误文本、退出码，以及会话文件的内容。

选这条接缝的理由：M1 的风险在模块交界处（配置解析、请求构造、SSE 分块、落盘顺序），单模块测试测不到；而这条接缝不依赖真实模型、不依赖网络，还能精确控制服务端返回什么。

代价是每次测试要启动一次进程，单条测试约几十毫秒。M1 总共不到二十条测试，可以接受。

### 什么算好测试

只断言外部可观察的行为：屏幕上的文字、磁盘上的文件、进程退出码。不断言内部函数、不检查私有结构、不依赖日志措辞的细节。测试名字描述用户场景，不描述实现。

### 假服务器

一个进程内的 HTTP 服务，监听随机端口，按测试给定的脚本响应：

- 支持按指定字节数切分响应体写入，用来制造"SSE 分块落在多字节字符中间"的场景。
- 记录收到的请求体，供测试断言模型名、系统提示内容、消息顺序。
- 可以编程返回 401、429（带或不带 `Retry-After`）、500、超时、空响应体、只有 `[DONE]` 的响应。

### 测试清单

1. 单轮成功：提示词出现、回答完整、退出码 0、会话文件三行且链正确。
2. 系统提示：请求体中包含内置提示、全局规则、项目规则，顺序正确。
3. 项目规则查找：在子目录启动，仍能找到上级的 `AGENTS.md`。
4. 规则文件缺失：不报错，请求里只有内置提示。
5. 模型覆盖：`--model` 改变请求里的模型名，会话里多一条 `model_change`。
6. 配置缺失：删掉 `base_url`，退出码 2，错误信息点名该字段，不发请求。
7. 上下文窗口为 0：退出码 2。
8. 401：退出码 1，错误信息提到 `BAIZE_API_KEY`，会话文件里没有助手消息。
9. 429 后成功：假服务器第一次返回 429、第二次返回正常流，最终退出码 0，且请求次数为二。
10. 连续 429：三次后退出码 1，请求次数为三，间隔符合预期（只断言顺序，不断言真实等待时长）。
11. 5xx：同上。
12. 400 不重试：只请求一次，退出码 1。
13. 流中途断开：已经输出的文本保留，退出码 1，会话里的助手消息带 `interrupted` 标记（若已写入）。
14. 任意分块：把 SSE 响应按 1 字节切分，输出与不切分时完全一致，中文不乱码。
15. 只有 `[DONE]`：助手消息内容为空，不崩溃。
16. 空输入：交互模式里输入空行不发请求。
17. 会话目录自动创建：`HOME` 指向全新临时目录，运行后目录和文件都存在。
18. 会话文件损坏：先写入一行坏 JSON，再加载时跳过并警告，不崩溃。
19. 文件占用：保持一个锁的前提下再启动同一会话，得到"已被占用"错误（这条可能需要等 M3 的 `--continue`，M1 可用直接打开同一路径的方式验证）。
20. `--version`：输出与 `Cargo.toml` 的版本一致。

### 先例

仓库目前没有任何测试，M1 的测试是第一批。它们会成为后续里程碑的模板：测试文件按场景命名，共享同一个假服务器辅助模块。

## Out of Scope

- 工具调用与工具循环（M2）。
- `--continue` / `--resume` 和会话选择界面（M3）。
- 上下文压缩（M4）。
- LSP 客户端（M5）。
- TUI（M6）。
- Anthropic 原生协议与 prompt cache（M7）。
- 树操作界面（M8）。
- 图片输入。
- 多模型角色。
- 项目级配置文件。
- 交互模式的多行编辑（`Alt+Enter`、粘贴保留换行）——M1 的交互模式只做单行输入。
- 语法高亮、markdown 渲染。
- 非 macOS 平台。

## Further Notes

**依赖需要辉哥确认后才能写进 `Cargo.toml`。** 运行时依赖：`tokio`、`serde`、`serde_json`、`toml`、`clap`、`reqwest`、`anyhow`、`thiserror`、`futures`、`time`、`fs2`。测试依赖：`tiny_http`、`assert_cmd`、`predicates`、`tempfile`。

**一个已知的简化：** M1 不做真正的 token 计数，只在请求前按字符数估算、请求后记录服务端返回的 `usage`。压缩阈值在 M4 才生效，所以这里不影响正确性。

**一个需要观察的点：** 本地网关是否支持 `stream_options.include_usage`。如果不支持，`usage` 就是空；这不算失败，M1 允许它缺失。

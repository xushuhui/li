# M2：工具循环与四个基础工具

Status: ready-for-agent

## Problem Statement

M1 之后，li 能对话，但只能聊天。它看不见仓库里的文件，改不了代码。用户问"把这个函数改成异步的"时，模型只能输出一段文字让他自己复制粘贴。

M2 要解决的是"能动手"：模型可以请求读取一个文件、写入内容、按行锚点修改、执行命令，li 执行后把结果交回给模型，模型继续推理，直到它认为可以停下来。

验收标准（设计文档第 8 节）：让它读一个文件并修改，改动落到磁盘。

## Solution

在 `provider` 与 `cli` 之间加一层工具执行。模型每轮的响应里除了文本，还可能带 `toolCall`；主循环把每个调用分发到对应工具，把结果作为 `toolResult` 消息写回会话并发给模型，重复直到模型不再请求工具。

四个工具：

- `read`：读文本文件，输出带 `[路径#标签]` 头和行号，同时记录内容快照。
- `write`：整文件覆盖。
- `edit`：用 `[路径#标签]` + 行操作修改，标签不匹配就拒绝。
- `bash`：执行命令，非白名单命令要用户确认。

## User Stories

1. 作为用户，我希望模型能主动请求读文件，这样我不用手动粘贴代码。
2. 作为用户，我希望 `read` 的输出带行号，这样模型能精确引用位置。
3. 作为用户，我希望 `read` 的输出带 `[路径#标签]` 头，这样后续 `edit` 能验证它读的是同一份内容。
4. 作为用户，我希望读超过 2000 行的文件时被截断并提示剩余行数，这样上下文不会被一个大文件撑爆。
5. 作为用户，我希望可以指定行范围读取，这样模型只看需要的那一段。
6. 作为用户，我希望 `write` 覆盖整个文件并返回写入字节数，这样新建文件有明确路径。
7. 作为用户，我希望 `edit` 按行号替换、插入、删除，这样模型不用重复粘贴旧内容。
8. 作为用户，我希望 `edit` 在文件已被改动时拒绝执行并提示重读，这样不会基于过期内容改错位置。
9. 作为用户，我希望 `edit` 只能改它读过的行，这样模型不能凭空捏造行号。
10. 作为用户，我希望 `bash` 执行命令并返回标准输出与标准错误，这样模型能跑测试。
11. 作为用户，我希望 `bash` 有超时，这样卡住的命令不会让整个会话挂死。
12. 作为用户，我希望 `bash` 的输出超过 2000 行或 200 KB 时被截断成摘要加首尾片段，这样上下文不会被日志淹没。
13. 作为用户，我希望只读命令（`ls`、`cat`、`git status`、`git diff`、`grep`、`find`、`rg`、`fd`）直接执行，这样常见的查看动作不需要每次确认。
14. 作为用户，我希望其他命令执行前问我 `y/n`，这样模型不会在我不知情时删东西。
15. 作为用户，我希望拒绝一次命令后模型得到明确的"用户拒绝"结果，这样它会换一种方式而不是重试同一条。
16. 作为用户，我希望同一轮的多个只读调用并行执行，这样读三个文件的等待时间不是三倍。
17. 作为用户，我希望写操作严格按模型给出的顺序执行，这样"改文件再跑测试"不会读到改之前的内容。
18. 作为用户，我希望每轮工具调用在终端上有一行摘要，这样我能看见它在做什么。
19. 作为用户，我希望工具出错时看到错误内容，而不是程序崩溃。
20. 作为用户，我希望工具循环有上限，这样模型陷入循环时不会无限跑下去。
21. 作为用户，我希望被中断的工具调用在会话里留下"已中断"的结果，这样下次打开时消息是成对的。
22. 作为用户，我希望 `read` 拒绝二进制文件并给出提示，这样模型不会把乱码塞进上下文。
23. 作为用户，我希望工具调用的参数是 JSON Schema 描述给模型的，这样模型知道每个参数怎么填。

## Implementation Decisions

### 消息模型扩展

助手消息的 `content` 增加 `toolCall` 块：`{"type":"toolCall","id","name","arguments"}`，其中 `arguments` 是 JSON 字符串。

新增 `toolResult` 角色：`{"role":"toolResult","toolCallId","toolName","content":[{"type":"text","text"}],"isError"}`。

`toolCall` 与 `toolResult` 必须成对。进程在两者之间被杀时，下次加载会话发现没有结果的 `toolCall`，补一条 `isError: true`、内容为"执行被中断"的结果。

### 工具接口

每个工具实现同一个异步 trait：名称、描述、JSON Schema、执行方法。执行结果包含输出文本、是否出错、可选的结构化附加数据。

工具集合用 `Box<dyn Tool>` 存放，按名称查找。M2 注册四个。

### 主循环

每轮：

1. 从当前可见路径构造消息。
2. 请求模型，收集文本与工具调用。
3. 把助手消息（含文本与调用）落盘。
4. 没有调用就结束本轮，回到提示符。
5. 有调用就分组执行：只读工具并行，其余按模型给出的顺序串行。
6. 每个结果作为 `toolResult` 落盘。
7. 回到第 1 步。

循环上限 64 轮，超过则中断并说明原因（防止模型自我循环）。

### read

输入：路径、可选起始行、可选行数。

行为：按行流式读取；跳过二进制文件（内容含 NUL 字节）；输出 `[路径#标签]` 头，随后每行 `行号:内容`；超过 2000 行时截断并在尾部提示总行数与已显示范围。

标签是文件内容规范化后的 4 位十六进制摘要。规范化：统一换行符为 `\n`，去掉行尾空白。同时把完整内容与行范围记入会话内的快照表。

### edit

输入是一个或多个 `[路径#标签]` 段，每段后跟行操作。M2 支持：

- `PUT N.=M:` 替换第 N 到 M 行（含两端），后跟以 `+` 开头的正文行。
- `PUT <N:` 在第 N 行之前插入。
- `PUT >N:` 在第 N 行之后插入。
- `PUT >$:` 追加到文件末尾。
- `CUT N.=M` 删除第 N 到 M 行。

行号指的是带标签快照里的原始行号，不是同一批操作中间的行号。所有操作先解析、校验、再一次性应用。

校验：标签必须存在于快照表；当前文件内容重新计算标签必须与之一致；操作范围必须落在该文件被读过的行范围内；范围必须有序且不重叠；正文与操作必须匹配（有正文的必须有 `+` 行，无正文的不能带 `+` 行）。

成功时返回新的 `[路径#标签]` 头（基于应用后的内容），并更新快照。

失败时返回明确原因：标签未知、内容已变（提示重读）、行号越界、范围重叠、缺少正文。

### write

输入：路径、完整内容。创建或覆盖，返回写入字节数。不检查快照，不要求先读。

### bash

输入：命令、超时秒数（默认 120，上限 600）。

执行：用系统 shell（`/bin/sh -c`）在会话工作目录里运行，捕获标准输出与标准错误，合并返回。超时则杀掉整个进程组。

审批：命令的第一个词（去掉环境变量赋值和路径前缀后）在只读白名单里就直接执行；否则向用户显示命令并等待 `y` / `n`。拒绝时返回 `isError: true`、内容"用户拒绝执行"。

输出截断：超过 2000 行或 200 KB 时保留前 100 行与后 100 行，中间用一行标注省略了多少。

### 快照表

进程内内存结构：路径 → 最近若干次快照（标签、规范化内容、可见行范围）。M2 每个路径保留最近 4 份。

不持久化。进程重启后需要重新 `read` 才能 `edit`，这是有意为之——跨进程恢复需要把快照写进会话文件，留给后续里程碑。

### 输出与审批界面

工具调用时打印一行 `▶ 名称 参数摘要`。工具结果只在出错或超过 5 行时打印首尾各 3 行。完整内容只写会话文件。

审批提示写标准错误，避免污染标准输出。

## Testing Decisions

沿用 M1 的唯一接缝：真实二进制 + 假模型服务器。M2 新增的是让假服务器返回带 `toolCalls` 的响应，然后断言磁盘上的结果。

新增测试：

1. 单次 `read`：请求一个临时文件，模型收到带标签头的内容。
2. `read` 行范围：只返回指定区间。
3. `read` 截断：2001 行文件被截断且提示总行数。
4. `read` 二进制：含 NUL 的文件被拒绝。
5. `write` 新建：文件出现在磁盘上，内容正确。
6. `write` 覆盖：旧内容被替换。
7. `edit` 替换：`PUT` 后文件内容正确，返回新标签。
8. `edit` 插入：`<N` 与 `>N` 的位置正确。
9. `edit` 删除：`CUT` 后行数减少。
10. `edit` 过期标签：先 read，再用另一进程改写文件，edit 被拒绝并提示重读。
11. `edit` 未读行：编辑快照范围之外的行被拒绝。
12. `edit` 参数缺失：缺少正文时报错。
13. `bash` 白名单：`cat` 直接执行。
14. `bash` 审批拒绝：非白名单命令在标准输入给 `n` 时返回"用户拒绝"。
15. `bash` 审批通过：给 `y` 时执行。
16. `bash` 超时：`sleep 5` 配 1 秒超时，返回超时错误。
17. `bash` 截断：输出 3000 行的命令，结果被截断且带省略标注。
18. 多轮闭环：模型先 read、再 edit、再结束，磁盘内容等于预期。
19. 并行只读：同一轮两个 read，两个结果都返回（顺序不保证）。
20. 循环上限：模型连续请求工具 65 轮后被中断。

测试里不启动真实的模型网关，也不依赖真实 shell 的具体版本——`bash` 测试只用 `sh` 内置或 `echo`/`cat`/`sleep` 这类 POSIX 命令。

## Out of Scope

- `grep` / `glob` 工具（M3 之前）。
- LSP（M5）。
- 上下文压缩（M4）。
- 跨进程快照恢复。
- 语法块锚点（`PUT N*:`）、命名寄存器、`MV`/`REM`（v2）。
- 图片、TUI、Anthropic 协议。

## Further Notes

**新依赖**：`async-trait`（工具 trait 需要对象安全）、`regex`（`edit` 的头部解析可以不用正则，若不用则不加）、`tokio` 的 `process` feature（`bash`）。

`bash` 的进程组杀灭在 macOS 上需要 `setsid` 或 `killpg`；实现时用 `tokio::process::Command::pre_exec` 设置进程组，或者简单地对子进程 `kill` 并接受孙进程可能残留。M2 先用简单方案，在代码里标 `SIMPLIFICATION`。

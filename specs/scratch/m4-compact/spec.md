# M4 上下文压缩

## 目标

对话接近模型上下文窗口时自动压缩：把历史换成一段固定结构的摘要，之后只带摘要继续，不丢最初的任务目标。

## 触发

每次请求模型前估算当前上下文的 token 数。超过 `context_window × compact_at_percent / 100` 就压缩一次。

配置来自 `~/.config/li/config.toml`：

```toml
[model]
context_window = 1000000

[context]
compact_at_percent = 80
```

## 做法

1. 把当前可见对话渲染成文本。单条消息截断到 2000 字符，工具结果 1200 字符。
2. 渲染结果超出预算时，保留第一条用户消息 + 最新的一段，中间省略。第一条用户消息通常就是任务目标。
3. 用同一个模型请求摘要，固定五节：目标、约束、已完成、待办、关键文件。
4. 摘要落成 `compaction` 条目，成为新的上下文起点。
5. 原消息一条不删，文件里保留完整历史。

## token 估算

不引入分词器。中文与全角字符按 1 字符 = 1 token，其余按 4 字符 = 1 token。每次响应后用模型返回的 `usage.input` 作为下界校正。

## 验收

- 造一个足够长的对话，压缩后模型仍能说出最初的任务目标。
- 压缩前后会话文件行数只增不减，原消息可读。
- 摘要请求本身的输入不超过模型窗口。
- 同一会话再次加载时，摘要仍然生效。

## 不做

- 自动分层摘要，一次压到底。
- 压缩前征求用户同意。
- 删除任何原有条目。
- 用摘要替换历史之外的其他压缩策略（例如丢弃最早的几条）。

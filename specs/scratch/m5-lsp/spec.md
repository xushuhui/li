# M5 LSP

## 目标

让 baize 直接问语言服务器：这个文件有什么错、这个符号在哪定义、被谁引用。不再只靠跑测试猜。

## 覆盖范围

先支持三种，按文件扩展名自动选择：

| 扩展名 | 服务器 | 启动参数 |
|---|---|---|
| `.go` | `gopls` | 无 |
| `.lua` | `lua-language-server` | 无 |
| `.rs` | `rust-analyzer` | 无 |

其他扩展名返回「没有对应的语言服务器」，不报错。

## 三个工具

- `diagnostics(path)`：返回该文件的错误与警告，带 1 起始的行列号与严重级别。
- `definition(path, line, column)`：返回符号定义的位置列表。
- `references(path, line, column)`：返回符号被引用的位置列表。

行号列号按人读的方式从 1 开始，与 `read` 工具输出一致。

## 客户端做法

1. 启动服务器子进程，走标准输入输出。
2. 消息用 LSP 规定的 `Content-Length: N\r\n\r\n{json}` 帧格式。
3. 请求带自增 id，响应按 id 匹配；超时 30 秒。
4. 打开文件用 `textDocument/didOpen` 发送完整内容。
5. 诊断是服务器主动推送的通知，按文件 URI 缓存，等待上限 5 秒后返回已收到的部分。
6. 同一个「服务器命令 + 项目根目录」复用一个进程，避免每次冷启动。

## 验收

- 写一个引用了未声明变量的 Go 文件，`diagnostics` 返回对应的编译错误，行号正确。
- 对 Go 函数的调用位置求 `definition`，能跳回函数声明所在行。
- 同一个 Go 项目连续调用两次，第二次不重启服务器。

## 不做

- 自动补全、重命名、代码格式化。
- 编辑器协议的完整实现（只做这三个查询需要的子集）。
- 在文件变更后主动通知服务器（每次查询前重新 `didOpen`）。
